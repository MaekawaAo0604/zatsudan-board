# 今日の雑談ネタを足す

雑談ボード（このリポジトリ）の `data/topics.json` に、今日の日付のネタを追加する。
定期実行では誰も確認しないので、迷ったら安全な側（足さない・コミットしない）に倒し、最後に何をしたかを報告する。

## 1. 今日の日付と現状を確かめる

1. リポジトリのルートで作業する（`data/topics.json` があるフォルダ）。
2. 今日の日付をこのパソコンの時刻で取る：`date +%F`（例 `2026-11-09`）。
3. `data/topics.json` を読む。形式は README の「毎日のネタの形式」のとおり。
4. 今日の日付の `days` 要素がすでにあるときは、引数に「追加」がなければ**何も変えずに終了**し、「今日の分は登録済み」と報告する。
   引数に「追加」があれば、その要素の `topics` の末尾に足す。
5. `git status --short` を見て、`data/topics.json` に未コミットの変更がすでにあるときは**変更せずに終了**し、そのことを報告する（人の作業を混ぜないため）。

## 2. ネタを考える

件数は引数の数、なければ **4 件**。

- 日本語で、チームやサークルの誰でも気軽に話せるもの。
- タイトルは 30 字以内、`detail` は話すきっかけになるひとことを 40 字以内（不要なら空文字）。
- 季節・曜日・年中行事など、今日の日付に合うものを 1 件以上入れる。
- 食べもの、趣味、休日、道具やアプリ、思い出、ちょっとした「もしも」など、種類を散らす。
- **過去 30 日分のタイトルと同じもの・ほぼ同じものは出さない。** 同じ日の既存のネタとも重ねない。
- 避けるもの：政治・宗教・選挙、収入やお金の具体的な話、健康や体型・容姿、恋愛や家族関係に踏み込むもの、特定の人や会社の噂、誰かが答えにくい・不快になりうるもの。
- 最新ニュースや事実を前提にしない（その日の出来事を確かめる手段がないため）。

## 3. data/topics.json を書き換える

- 今日の要素がなければ `days` の末尾に `{ "date": "<今日>", "topics": [...] }` を追加する。
- `id` は `<今日>-<連番>`。今日の既存ネタがあれば、その最大の連番の次から振る。
- 既存の日付やネタ、ファイルのほかの部分は変えない。インデントは既存に合わせる（2 スペース、1 ネタ 1 行）。

書いたら検証する：

```bash
node .claude/skills/add-daily-topics/validate.mjs data/topics.json
```

エラーが出たら直して再実行する。直せないときは `git checkout -- data/topics.json` で元に戻し、コミットせずにエラー内容を報告する。

## 4. コミットする

`data/topics.json` **だけ**をコミットする。ほかのファイルはステージしない。プッシュはしない。

```bash
git add data/topics.json
git commit -m "今日の雑談ネタを追加 (<今日>)" -m "Co-Authored-By: Claude <noreply@anthropic.com>"
```

`Co-Authored-By` の行は、そのときの環境で指定されている帰属表記があればそれに合わせる。

## 5. 報告する

足した日付、件数、各ネタのタイトルとコミットのハッシュを短く報告する。足さなかった・コミットしなかった場合はその理由を書く。
