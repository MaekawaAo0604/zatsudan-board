# 今日の雑談ネタを足す

雑談ボード（このリポジトリ）の `data/topics.json` に、今日の日付のネタを追加する。
定期実行では誰も確認しないので、迷ったら安全な側（足さない・コミットしない・プッシュしない）に倒し、最後に何をしたかを報告する。

## コマンドの打ち方（定期実行で止まらないために）

定期実行では、許可を求められても誰も答えない。そこで、ここに書いたコマンドは `.claude/settings.json` で許可してある。
**許可ルールに当たるように、次を必ず守る。**

- Bash は **1回に1コマンド**だけ打つ。この手順に書いたコマンドを、**書いたとおりそのまま**打つ。
- `&&`、`;`、`|`、`$(…)`、変数（`H=…`、`"$H"`）、リダイレクト（`>`）、引用符でくくった文字を足さない。前のコマンドの出力が要るときは、出力を読み、次のコマンドに文字のまま書き込む。
- この手順にないコマンドは打たない。ファイルを読むときは Read を、書き換えるときは Edit を使う。

まとめて打つと「引用符の中を確かめられない」などの理由で許可ルールに当たらなくなり、許可を待ったまま止まる。

## 0. 作業するブランチを整える

`data/topics.json` を読んだり書き換えたりする前に、いちばん最初に次のコマンドをそのまま打つ。`git switch` や `git checkout main` を自分で打たない。

```bash
bash .claude/skills/add-daily-topics/prepare-main.sh
```

- **手元では何もしない。** そのまま手順 1 に進む。
- **クラウドでは、`claude/` ではじまるブランチから最新の `main` に移る。** このあとは `main` で作業し、プッシュ先も `main`（手順 5 の条件どおり）。`claude/` のブランチには戻らない。
- 「main に移らない」で終わったときは、**何も書き換えずに**理由を報告して終了する。

## 1. 今日の日付と現状を確かめる

1. リポジトリのルートで作業する（`data/topics.json` があるフォルダ）。
2. 今日の日付をこのパソコンの時刻で取る（例 `2026-11-09`）：

   ```bash
   date +%F
   ```

3. `data/topics.json` を Read で読む。形式は README の「毎日のネタの形式」のとおり。
4. 今日の日付の `days` 要素がすでにあるときは、引数に「追加」がなければ**何も変えずに終了**し、「今日の分は登録済み」と報告する。
   引数に「追加」があれば、その要素の `topics` の末尾に足す。
5. 次のコマンドで状態を見る。`data/topics.json` に未コミットの変更がすでにあるとき、またはステージされている変更があるときは、**変更せずに終了**し、そのことを報告する（人の作業を混ぜないため）。

   ```bash
   git status --short
   ```

## 2. ネタを考える

件数は引数の数、なければ **4 件**。

- 日本語で、チームやサークルの誰でも気軽に話せるもの。
- タイトルは 30 字以内、`detail` は話すきっかけになるひとことを 40 字以内（不要なら空文字）。
- 季節・曜日・年中行事など、今日の日付に合うものを 1 件以上入れる。
- 食べもの、趣味、休日、道具やアプリ、思い出、ちょっとした「もしも」など、種類を散らす。
- **過去 30 日分のタイトルと同じもの・ほぼ同じものは出さない。** 同じ日の既存のネタとも重ねない。
- 避けるもの：政治・宗教・選挙、収入やお金の具体的な話、健康や体型・容姿、恋愛や家族関係に踏み込むもの、特定の人や会社の噂、誰かが答えにくい・不快になりうるもの。
- **気持ちが沈むものも避ける**：病気・死別・災害・事件、失敗談、悩み・不安・後悔など。答えがそうなりやすい聞き方も避け、迷ったら別のネタにする。
- 最新ニュースや事実を前提にしない（その日の出来事を確かめる手段がないため）。

## 3. data/topics.json を書き換える

Edit で書き換える。

- 今日の要素がなければ `days` の末尾に `{ "date": "<今日>", "topics": [...] }` を追加する。
- `id` は `<今日>-<連番>`。今日の既存ネタがあれば、その最大の連番の次から振る。
- 既存の日付やネタ、ファイルのほかの部分は変えない。インデントは既存に合わせる（2 スペース、1 ネタ 1 行）。

書いたら検証する：

```bash
node .claude/skills/add-daily-topics/validate.mjs data/topics.json
```

エラーが出たら Edit で直して再実行する。直せないときは次のコマンドで元に戻し、コミットせずにエラー内容を報告する。

```bash
git checkout -- data/topics.json
```

## 4. コミットする

次のコマンドを、引数を付けずにそのまま打つ。`git add` や `git commit` を自分で打たない。

```bash
bash .claude/skills/add-daily-topics/commit-today.sh
```

スクリプトは `data/topics.json` **だけ**をステージし、件名「今日の雑談ネタを追加 (<今日>)」と `Co-Authored-By: Claude <noreply@anthropic.com>` の行を付けてコミットする。
成功すると最後の行に `コミットした：<ハッシュ>` と出る。このハッシュを次の手順で使う。
「コミットしない」で終わったときは、出た理由を報告して終了する（プッシュもしない）。

## 5. プッシュする

**この実行でコミットしたときだけ**、手順 4 で出たハッシュを文字のまま書き込んで、次を実行する。
コミットしなかったとき（今日の分が登録済み、未コミットの変更があった、検証が通らなかった、コミットのスクリプトが止まった）は、プッシュしない。

```bash
bash .claude/skills/add-daily-topics/push-today.sh <手順 4 で出たハッシュ>
```

例：`bash .claude/skills/add-daily-topics/push-today.sh 762d444c0e1f…`（ハッシュを引用符でくくらない）

スクリプトは、次の条件がすべてそろったときだけ `origin/main` にプッシュする。

- 今のブランチが `main` で、いちばん新しいコミットが渡したコミットである。
- そのコミットは件名が「今日の雑談ネタを追加 (<今日>)」で、`data/topics.json` だけを変えている。
- `origin/main` を取得したうえで、手元が `origin/main` より先にあるのはそのコミット1件だけで、`origin/main` に手元にないコミットはない。

スクリプトが「プッシュしない」で終わったときは、**自分でプッシュし直さない。** `git push` を直接打つこと、`--force`、rebase や pull で合わせることはしない。コミットは手元に残したまま、出た理由を報告する（人があとで確かめてプッシュする）。

## 6. 報告する

足した日付、件数、各ネタのタイトル、コミットのハッシュ、プッシュしたかどうかを短く報告する。足さなかった・コミットしなかった・プッシュしなかった場合はその理由を書く。
